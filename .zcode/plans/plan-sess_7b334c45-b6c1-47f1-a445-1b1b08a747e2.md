接入 xmail 系列扩展库（xmail + xsmtp + xpop3 + ximap，4 变体 + 自动依赖）

## 背景与关键结论（已完成探索）

- xrt 的邮件家族是 **4 个兄弟库**（commit `6bbb256e`，2026-09-14 拆分）：`xmail`（MIME 解析/构造基础层，89 个公开函数）+ `xsmtp`（43）/ `xpop3`（47）/ `ximap`（101）三个协议客户端，**协议库均硬依赖 xmail**（公开头 `<xmail.h>` + 内部相对桥 `../../xmail/src/internal/*`）。
- **兼容性已验证**：xserver vendored `lib/xrt.h`（钉在 `2639487c`，是 `6bbb256e` 的直系祖先且两者间零核心改动）完整覆盖四库用到的全部 85 个 xrt 函数与 17 个 XRT_MODULE_* 宏，**无需刷新 xrt，无需新增链接库**（全部走 xrt 动态加载）。
- **单头方案不可用**（本次探索的关键否定结论）：`single/x*.h` 把内嵌的 xrt 核心实现、xmail 实现、协议实现全部圈在同一个 `X<LIB>_IMPLEMENTATION` 门内，在 xserver 编译会与 main.c 的全量 xrt 实现冲突。必须走**源码树 vendoring**。
- 与 xllm 模式的差异及对策：公开头非自包含（引 `<xrt/*.h>` 模块头）→ 用一层指向 `<xrt_decl.h>` 的 shim 解决（宿主与 VFS 通吃，xrt_decl.h 无门控全量声明）；无现成 unity TU → 自写 4 个；绑定角色由生成的 `include/x*/features.h` 承担（`X<LIB>_MODULE_ALL` → 特性/XRT 模块闭包）。

## 实施步骤

1. **注册表支持 `requires`**（`tools/xs_extensions.py`）：`select_extensions()` 传递闭包展开依赖（协议项自动携带 xmail），未知/循环依赖报错；`load_registry` 校验该字段合法引用；保持既有"新增库不改构建驱动"原则（requires 是清单声明的一部分）。同步补单测（自动展开、去重、顺序稳定、坏引用报错）。注意现有注册表已含 `xllm-session` 条目，不扰动。

2. **Vendor 四库到 `lib/{xmail,xsmtp,xpop3,ximap}`**（保持兄弟目录，相对桥不破）：每库收 `include/`、`src/`、`config/modules.json`、`README.md`；**不收** `single/`（4×8MB，不可用）、`tests/`、`bench/`、`docs/`、`examples/`。每库写 `UPSTREAM.txt`（来源 xrt@6bbb256e、拆分说明、同步时需重验 import 表）。

3. **Shim 层 `lib/xmail/shim/xrt/<core>.h`**：实现时先 grep 四库全部 `#include <xrt/…>`，对其中 **xrt 核心模块名**（error/charset/time/memory/codec/tcp/tls_stream/buffer/compress/random 等，排除 mail*/smtp*/pop3*/imap* 这些随库 vendored 的真头）逐个生成一行文件 `#include <xrt_decl.h>`（include guard 相同则天然幂等）。

4. **自写 4 个 unity TU**（对齐 `lib/xllm/xllm.c` 模式）：
   - `lib/xmail/xmail.c`：`#define XMAIL_MODULE_ALL` + `#include <xmail.h>` + `src/mail/*.c`（14）+ `src/transport/*.c`（5）
   - `lib/xsmtp/xsmtp.c`：`XSMTP_MODULE_ALL` + `<xsmtp.h>` + `src/smtp/*.c`（4）——xmail 源码只在 xmail TU 编译一次，组合变体无重复符号
   - `lib/xpop3/xpop3.c`（5 源）、`lib/ximap/ximap.c`（9 源）同理
   - 验证点：xsmtp TU 内部头经 `../../xmail/src/internal/…` 取到共享 transport/SASL 声明（定义在 xmail TU，链接期汇合）

5. **注册 `tools/extensions.json` 四条目**：
   - `xmail`：宏 `XS_USE_XMAIL`，headers = `{xmail.h, xrt.h→shim, xrt/mail.h …16 个模块头, xrt/<shim 名>…}`（VFS 打包保留 `xrt/` 子路径，脚本 `#include <xmail.h>` 全链可解析），sources = `[lib/xmail/xmail.c + include flags]`
   - `xsmtp`/`xpop3`/`ximap`：宏 `XS_USE_XSMTP/XPOP3/XIMAP`，各自 umbrella + 模块头，sources 带 `-Ilib/xmail/include -Ilib/xmail/shim -Ilib/<proto>/include`，**`"requires": ["xmail"]`**
   - 不声明 link_flags

6. **四张符号表**：`src/script/import_{xmail,xsmtp,xpop3,ximap}.inc`（89+43+47+101，宏 `XS_XMAIL_SYMBOL` 等；探索报告已有逐函数清单，按模块分组注释）。

7. **测试**：
   - `tools/test_extensions.py`：×4 头文件-清单覆盖测试（扫 `XRT_API` 外部声明 ≡ inc 集合）；requires 展开测试；组合（xsmtp+xpop3）不重复选 xmail 测试
   - `tools/test_extensions_runtime.py`：掩码扩到 8/16/32/64；离线探针——xmail：compose→parse 往返、QP/Base64 编解码；xsmtp：应答行/能力解析、命令写；xpop3：STAT/LIST/UIDL 解析；ximap：响应/序列集/数据项解析；嵌套 TCC 可见性；default 变体下四组头+符号缺失

8. **构建验证矩阵**（Windows）：`default`、`xmail`、`xsmtp`、`xpop3`、`ximap`、`xsmtp xpop3 ximap`（= 全家，验不重复编 xmail）、`sqlite xtp xllm xmail xsmtp xpop3 ximap`（超级变体）；每个跑运行时探针；确认现有 sqlite/xtp/xllm/xllm-session 回归不受影响。

9. **发布与文档**：`tools/make_release.py` 标签 → "full (sqlite + xtp2 + xllm + xmail)"（Linux 双二进制需在 Linux 侧重建成后打包，Windows 先行）；`docs/可选扩展库.md`（变体表 + requires 机制说明 + 四库定位/符号数/vendoring 说明/shim 说明 + 验证记录）；`README.md`、`build.bat`/`build.sh` 用法注释补四个库名。
