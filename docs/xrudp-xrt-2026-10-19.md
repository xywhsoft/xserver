# xrudp service verification after the XRT update

The committed XRT snapshot is `3d55ec41e13f0884ffe840d44a57a0189d9310f3`,
integrated by XS `6bc2fd84765ac2dc94e03a78438eea2a06e9d3d3`. The public
declarations and native runtime are updated together.

Fresh xrudp-only hosts were built with Windows GCC 16.2 and Linux Clang 21.
Both passed `tools/xrudp_service_test.py`, including real IPv4/IPv6 byte streams,
messages/game datagrams, pins/application context, reentrant abort, retained
connections across reload, rejected reload rollback, disable and joined exit.

The two builds have the same source digest:
`09c4b976fc049a73bfc4ce6e7ebcceea6e9b93b33b105d7dfad5a4b26a84939a`.
The Windows host SHA-256 is
`1dec4d358446d2be7710319668df5709265dc0a67933ec09bbb5ed0adfe997b4`;
the Linux host SHA-256 is
`54ca0a681426bb389eb7cd367f94729421c357feea5eb1cbe438cb453588ee3f`.
The Linux build's revision banner contains `-dirty`; its recorded source digest
matches the clean Windows build, and the repository was clean after both builds.
This banner is preserved in the evidence rather than rewritten.

Private build and process logs are `.build/xrudp-congestion-service-*-build.log`
and `.build/xrudp-congestion-service-*-test.log`; adjacent binary receipts record
the build inputs and hashes. These isolated artifacts were not installed or
released. This service gate does not establish Android or 72-hour stability.
