# XServer 服务热加载

XServer 当前有两条热加载链路：

- 脚本级热加载：面向 HTTP / WebSocket 的 Host 脚本
- 配置级热加载：面向整个运行时配置和指定 service 的差异化重建

前者通过脚本 API 直接在业务侧触发；后者通过运行时 `reload_config` 能力完成。

---

## 脚本级热加载 API

### xsReloadCurrentHost

热加载当前 Host 的脚本。

```c
int xsReloadCurrentHost(XS_ServerObject objServer, XS_HostObject objHost, int bForce);
```

**参数：**

- `objServer` - 当前服务对象
- `objHost` - 当前 Host 对象
- `bForce` - 预留参数，当前实现未区分 `0/1`，建议固定传 `1`

**返回值：**

- `0` - 成功
- 负数 - 失败，见下方错误码表

**示例：**

```c
bool RequestProc(XS_ServerObject objServer, XS_HostObject objHost, XS_RequestObject objReq, XS_ResponseObject objResp)
{
	char sBody[64];
	int iRet;

	if ( strcmp(xsReqPath(objReq), "/_reload") != 0 ) {
		return false;
	}

	iRet = xsReloadCurrentHost(objServer, objHost, 1);
	snprintf(sBody, sizeof(sBody), "{\"code\":%d}", iRet);
	return xsHttpJson(objResp, 200, "OK", sBody) != 0;
}
```

---

### xsReloadHostByName

按 Host 名称热加载脚本。

```c
int xsReloadHostByName(XS_ServerObject objServer, const char* sHostName, int bForce);
```

**参数：**

- `objServer` - 当前服务对象
- `sHostName` - Host 名称，对应配置中的 `name`
- `bForce` - 预留参数，当前实现未区分 `0/1`

**返回值：**

- `0` - 成功
- 负数 - 失败，见下方错误码表

**示例：**

```c
int iRet = xsReloadHostByName(objServer, "admin", 1);
```

---

## 错误码

| 错误码 | 含义 |
|--------|------|
| `0` | 成功 |
| `-1` | 目标无效，或 Host 不存在 |
| `-2` | 目标 Host 不是 `script-c` |
| `-3` | 重载失败 |
| `-4` | 重载忙，已有重载过程正在执行 |

---

## 热加载流程

热加载时会按以下顺序执行：

1. 调用旧脚本的 `ServiceUnit`，释放脚本持有的资源
2. 销毁旧的 TCC 状态
3. 创建新的 TCC 编译环境
4. 读取并编译新的 `devfile`
5. 完成重定位并绑定脚本符号
6. 调用 `XS_SetGlobalDate` 传递全局数据
7. 调用新脚本的 `ServiceInit`

---

## 配置级热加载能力

当前 `reload_config` 已经支持：

- 全量配置重载
- 按 `server` 定向重载
- HTTP / WS 的 Host 原位 reload
- `http / ws / tcp / udp / xtp / custom` 的 targeted server soft reload
- 纯 service add/remove 的短路重建
- 失败回滚

当前已经覆盖的差异化重建范围：

- `http`：`bind / backlog / recv_limit`
- `ws`：`bind / tls / ws_protocol / ws_message_limit / backlog`
- `custom / tcp`：主 listener 的 `bind / backlog / recv_limit`
- `udp`：对象级 `recv_limit / backlog`
- `xtp`：主 listener 与 TLS listener 的 `backlog / recv_limit / tls / port_tls / tls_cert / tls_key`

当前这条链路已经足够支撑 production `xs` 交付，剩余工作主要只是继续压缩到更细粒度的 listener / object 级最小替换。

---

## 注意事项

1. **脚本 API 仅适用于 Host 脚本** - 当前对脚本导出的 `xsReloadCurrentHost / xsReloadHostByName` 面向 HTTP / WebSocket Host；XTP / TCP / UDP / Custom 的 Service 级脚本不走这套接口
2. **仅支持 `devlang: "c"`** - 静态 Host 或其他脚本类型不能用这两个 API
3. **先做好资源释放** - 热加载前会先执行旧脚本的 `ServiceUnit`
4. **并发期间会切换版本** - 正在处理中的旧请求可能继续跑旧回调，新请求会进入新脚本
5. **编译失败会返回错误码** - 应在业务层明确把错误码返回给调用方，便于定位问题
6. **配置级 reload 和脚本级 reload 是两条链路** - 脚本 API 解决 Host 脚本替换；`reload_config` 解决 service / listener / 配置层差异化重建

## 典型应用场景

### 1. 通过 HTTP 接口重载当前 Host

```c
bool RequestProc(XS_ServerObject objServer, XS_HostObject objHost, XS_RequestObject objReq, XS_ResponseObject objResp)
{
	char sBody[64];
	int iRet;

	if ( strcmp(xsReqPath(objReq), "/_reload") != 0 ) {
		return false;
	}

	iRet = xsReloadCurrentHost(objServer, objHost, 1);
	snprintf(sBody, sizeof(sBody), "{\"code\":%d}", iRet);
	return xsHttpJson(objResp, 200, "OK", sBody) != 0;
}
```

### 2. 通过管理脚本重载指定 Host

```c
bool RequestProc(XS_ServerObject objServer, XS_HostObject objHost, XS_RequestObject objReq, XS_ResponseObject objResp)
{
	int iRet;

	if ( strcmp(xsReqPath(objReq), "/_reload_admin") != 0 ) {
		return false;
	}

	iRet = xsReloadHostByName(objServer, "admin", 1);
	if ( iRet != 0 ) {
		return Ret500(objServer, objHost, objReq, objResp, "reload admin failed", NULL) != 0;
	}

	return xsHttpText(objResp, 200, "OK", "reload admin ok\n") != 0;
}
```
