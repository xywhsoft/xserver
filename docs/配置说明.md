# XServer 配置说明

XServer 通过 `xs.json` 文件进行配置。当前主线只支持固定的根对象格式，服务列表统一放在 `services` 数组中。

---

## 命令行启动

### 基本用法

```bash
# Windows
xs.exe [配置文件路径]

# Linux
./xs [配置文件路径]
```

### 参数说明

| 参数 | 说明 |
|------|------|
| 配置文件路径 | 可选，指定要加载的配置文件。不指定则默认加载同目录下的 `xs.json` |

### 启动示例

```bash
# 使用默认配置文件 xs.json
xs.exe

# 指定配置文件（开发环境）
xs.exe dev.json

# 指定配置文件（生产环境）
xs.exe prod.json

# 指定配置文件（测试环境）
xs.exe test.json

# 使用绝对路径
xs.exe D:\config\myserver.json
xs.exe /etc/xserver/production.json
```

### 多环境配置管理

建议为不同环境创建独立的配置文件：

```
release/
├── xs.exe
├── xs.json          # 默认配置（开发环境）
├── xs.dev.json      # 开发环境配置
├── xs.test.json     # 测试环境配置
├── xs.prod.json     # 生产环境配置
└── wwwroot/
```

不同环境的配置差异通常包括：
- **端口** - 开发环境可能使用 8080，生产使用 80
- **调试模式** - 开发环境 `debug: true`，生产环境 `debug: false`
- **TLS** - 生产环境启用 HTTPS
- **路径** - 不同环境指向不同的脚本或资源目录

## 配置文件格式

`xs.json` 固定为一个根对象，服务列表放在 `services` 数组中。根对象同时可放置全局页面配置，例如 `default_page / page_404 / page_403 / page_500 / error_page`，也兼容中文键名。

```json
{
	"services": [
		{ "enabled": true, "class": "http", ... },
		{ "enabled": true, "class": "ws", ... }
	],
	"default_page": "index.html",
	"page_404": "wwwroot/error_404.xtl",
	"page_403": "wwwroot/error_403.html",
	"page_500": "wwwroot/error_500.xtl",
	"error_page": "wwwroot/error_generic.html"
}
```

注意：

- 根节点不再支持“数组表示多服务、字典表示单服务”的旧格式
- `services` 必须是数组，即使只启动一个服务也要写成数组
- 后续文档中的“服务配置”示例，如果只展示单个服务对象，表示它是 `services` 数组中的一个成员

## 服务配置

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `enabled` | bool | 是 | 是否启用服务 |
| `class` | string | 是 | 服务类型（见下表） |
| `name` | string | 否 | 服务名称 |
| `desc` | string | 否 | 服务描述 |
| `param` | string | 否 | 启动参数（供脚本使用） |
| `ip` | string | 是* | 绑定 IP 地址 |
| `port` | integer | 是* | 绑定端口 |
| `tls` | bool | 否 | 是否启用 TLS 1.3 加密 |
| `ip_tls` | string | 否 | TLS 绑定 IP 地址 |
| `port_tls` | integer | 否 | TLS 绑定端口 |
| `default_page` | string | 否 | 默认页文件路径 |
| `page_404` | string | 否 | 404 页面文件路径 |
| `page_403` | string | 否 | 403 页面文件路径 |
| `page_500` | string | 否 | 500 页面文件路径 |
| `error_page` | string | 否 | 通用错误页文件路径 |
| `path` | string | XTP/TCP/UDP/Custom 常用 | Service 级脚本或资源根目录 |
| `devlang` | string | 否 | Service 级开发模式（见下表） |
| `devfile` | string | 否 | Service 级入口脚本文件 |
| `host_default` | object | HTTP/WS 必填 | 默认主机配置 |
| `hosts` | array | 否 | HTTP/WS 虚拟主机列表 |

> *注：旧版 `addr / addr_tls` URL 风格字段已废弃，当前统一使用 `ip / port / ip_tls / port_tls`

### 服务类型 (class)

| 值 | 说明 |
|------|------|
| `http` | HTTP/HTTPS 服务 |
| `ws` | WebSocket/WSS 服务 |
| `xtp` | XTP 协议服务（轻量级二进制协议） |
| `tcp` | 原始 TCP 服务 |
| `udp` | UDP 服务 |
| `custom` | 自定义服务（通过回调函数实现） |

### 绑定字段格式

```
ip       -> 0.0.0.0
port     -> 80
ip_tls   -> 0.0.0.0
port_tls -> 443
```

## 主机配置 (Host)

HTTP/WS 服务可以服务多个虚拟主机，通过 `host_default` 配置默认主机，通过 `hosts` 数组配置多个虚拟主机。TCP/UDP/XTP/Custom 这类非 HostAware 服务直接使用 Service 级的 `path / devlang / devfile`。

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `enabled` | bool | 是 | 是否启用主机 |
| `name` | string | 否 | 主机名称 |
| `desc` | string | 否 | 主机描述 |
| `param` | string | 否 | 启动参数（供脚本使用） |
| `host` | string | 否 | 绑定域名，多个域名用 `;` 分隔 |
| `path` | string | 是 | 主机根目录（支持相对/绝对路径） |
| `default_page` | string | 否 | 默认页文件路径，未配置时默认 `index.html` |
| `page_404` | string | 否 | 404 页面文件路径 |
| `page_403` | string | 否 | 403 页面文件路径 |
| `page_500` | string | 否 | 500 页面文件路径 |
| `error_page` | string | 否 | 通用错误页文件路径 |
| `debug` | bool | 否 | 是否开启调试模式 |
| `devlang` | string | 否 | Host 开发模式（见下表） |
| `devfile` | string | 否 | 入口脚本文件路径 |
| `tls_ca` | string | 否 | TLS CA 证书文件路径 |
| `tls_cert` | string | 否 | TLS 证书文件路径 |
| `tls_key` | string | 否 | TLS 私钥文件路径 |

### 开发语言 (devlang)

#### Host 级 `devlang`（`host_default / hosts`）

| 值 | 说明 |
|------|------|
| `static` | 静态页面（默认值） |
| `c` / `script-c` | C 语言脚本（TCC 动态编译） |

#### Service 级 `devlang`（XTP / TCP / UDP / Custom）

| 值 | 说明 |
|------|------|
| `protocol` | 使用宿主内建协议处理（默认值） |
| `c` / `script-c` | C 语言脚本（TCC 动态编译） |

### 路径说明

- **相对路径**：以 `xs.exe` 所在目录为基准
- **绝对路径**：
  - Windows：包含 `:` 的路径，如 `D:\www`
  - Linux：以 `/` 开头的路径，如 `/var/www`
- **错误页继承**：Host 未配置页面字段时，继承所属 Service；Service 未配置时，再继承根对象配置
- **模板规则**：`page_404 / page_403 / page_500 / error_page` 后缀为 `.xtl` 时按模板渲染，否则按 HTML 原文返回

### 默认页与错误页返回说明

- `default_page` 未配置时默认使用 `index.html`
- `page_404 / page_403 / page_500 / error_page` 支持静态 HTML 文件，也支持 `.xtl` 模板
- 返回侧当前已经补齐 `Ret404 / Ret403 / Ret500 / RetError` 这类 API，用于在业务层统一返回错误页
- 传入模板变量时会做模板渲染；传 `NULL` 时按静态页处理

## 回调函数

当 `devlang` 设置为 `c` 或 `script-c` 时，XServer 会编译 `devfile` 指定的脚本，并调用以下回调函数：

### HostAware 服务（HTTP / WebSocket）

| 函数 | 说明 | 调用时机 |
|------|------|----------|
| `ServiceInit` | Host 脚本初始化 | 脚本加载后 |
| `ServiceStart` | Host 启动通知 | 服务启动时 |
| `ServiceStop` | Host 停止通知 | 服务停止时 |
| `ServiceUnit` | Host 脚本清理 | 停止或热加载前 |
| `RequestProc` | HTTP 请求回调 | 收到 HTTP 请求时 |
| `MessageProc` | 总线消息回调 | 收到总线消息时 |
| `WsOpenProc` | WebSocket 打开回调 | 握手完成时 |
| `WsTextProc` | WebSocket 文本帧回调 | 收到文本帧时 |
| `WsBinaryProc` | WebSocket 二进制帧回调 | 收到二进制帧时 |
| `WsPingProc` | WebSocket ping 回调 | 收到 ping 时 |
| `WsPongProc` | WebSocket pong 回调 | 收到 pong 时 |
| `WsCloseProc` | WebSocket 关闭回调 | 连接关闭时 |
| `XS_SetGlobalDate` | 全局数据传递 | 脚本加载后由 XS 调用 |

### ServiceAware 服务（XTP / TCP / UDP / Custom）

| 函数 | 说明 | 调用时机 |
|------|------|----------|
| `ServiceInit` | 服务脚本初始化 | 脚本加载后 |
| `ServiceStart` | 服务启动通知 | 服务启动时 |
| `ServiceStop` | 服务停止通知 | 服务停止时 |
| `ServiceUnit` | 服务脚本清理 | 停止前 |
| `MessageProc` | 总线消息回调 | 收到总线消息时 |
| `EventOpenProc` | 流连接打开回调 | TCP / XTP / Custom 打开连接时 |
| `EventDataProc` | 流数据回调 | TCP / Custom 收到数据时 |
| `EventCloseProc` | 流连接关闭回调 | TCP / XTP / Custom 关闭连接时 |
| `EventDgramProc` | UDP 数据报回调 | UDP 收到数据报时 |
| `EventXtpProc` | XTP 消息回调 | XTP 收到完整消息时 |
| `XS_SetGlobalDate` | 全局数据传递 | 脚本加载后由 XS 调用 |

### 回调函数签名

```c
// 服务初始化
void ServiceInit(XS_ServerObject objServer, XS_HostObject objHost);

// 服务启动
void ServiceStart(XS_ServerObject objServer, XS_HostObject objHost);

// 服务停止
void ServiceStop(XS_ServerObject objServer, XS_HostObject objHost);

// 服务清理
void ServiceUnit(XS_ServerObject objServer, XS_HostObject objHost);

// HTTP 请求回调
// 返回值：true=已处理，false=继续默认处理
bool RequestProc(XS_ServerObject objServer, XS_HostObject objHost, XS_RequestObject objReq, XS_ResponseObject objResp);

// 总线消息回调
bool MessageProc(XS_ServerObject objServer, XS_HostObject objHost, const char* sTopic, int64_t iDataID, xvalue objArgs);

// WebSocket 回调
void WsOpenProc(XS_ServerObject objServer, XS_HostObject objHost, void* pConn);
bool WsTextProc(XS_ServerObject objServer, XS_HostObject objHost, void* pConn, const char* pData, size_t iLen);
bool WsBinaryProc(XS_ServerObject objServer, XS_HostObject objHost, void* pConn, const void* pData, size_t iLen);
void WsPingProc(XS_ServerObject objServer, XS_HostObject objHost, void* pConn, const void* pData, size_t iLen);
void WsPongProc(XS_ServerObject objServer, XS_HostObject objHost, void* pConn, const void* pData, size_t iLen);
void WsCloseProc(XS_ServerObject objServer, XS_HostObject objHost, void* pConn, int iReason);

// 流式服务回调（TCP / XTP / Custom）
void EventOpenProc(XS_ServerObject objServer, void* pStream);
bool EventDataProc(XS_ServerObject objServer, void* pStream, const void* pData, size_t iLen);
void EventCloseProc(XS_ServerObject objServer, void* pStream, int iReason);

// UDP 回调
bool EventDgramProc(XS_ServerObject objServer, void* pSock, const void* pFromAddr, const void* pData, size_t iLen);

// XTP 回调
bool EventXtpProc(XS_ServerObject objServer, void* pStream, void* pMsg);

// 全局数据传递
void XS_SetGlobalDate(int idx, void* ptr);
```

## 配置示例

### HTTP 服务

```json
{
	"services": [
		{
			"enabled": true,
			"class": "http",
			"name": "Web Server",
			"desc": "主站点服务",
			"ip": "0.0.0.0",
			"port": 80,
			"tls": true,
			"ip_tls": "0.0.0.0",
			"port_tls": 443,
			"host_default": {
				"enabled": true,
				"name": "默认主机",
				"path": "wwwroot",
				"tls_cert": "tls/cert.pem",
				"tls_key": "tls/key.pem",
				"devlang": "c",
				"devfile": "script/main.c"
			},
			"hosts": [
				{
					"enabled": true,
					"name": "API 服务",
					"host": "api.example.com",
					"path": "api",
					"devlang": "c",
					"devfile": "api/main.c"
				}
			]
		}
	]
}
```

### WebSocket 服务

```json
{
	"services": [
		{
			"enabled": true,
			"class": "ws",
			"name": "WebSocket Server",
			"ip": "0.0.0.0",
			"port": 8080,
			"tls": true,
			"ip_tls": "0.0.0.0",
			"port_tls": 8443,
			"host_default": {
				"enabled": true,
				"name": "默认主机",

				"tls_cert": "tls/cert.pem",
				"tls_key": "tls/key.pem",

		{

			"devlang": "c",
			"devfile": "script_vnext/custom_main.c"
		}
	]
}
```

## TLS 证书配置

启用 TLS 时需要配置证书文件：

```json
{
	"services": [
		{
			"tls": true,
			"ip_tls": "0.0.0.0",
			"port_tls": 443,
			"host_default": {
				"tls_ca": "tls/ca.pem",
				"tls_cert": "tls/cert.pem",
				"tls_key": "tls/key.pem"
			}
		}
	]
}
```

每个虚拟主机可以配置独立的证书，支持 SNI（服务器名称指示）。
