# XServer 配置说明

XServer 通过 `xs.json` 文件进行配置，支持启动单个或多个服务。

---

## 命令行启动

### 基本用法

```bash
# Windows
xs.exe [配置文件路径]

# Linux
./xs [配置文件路径]
```

### 参数说明

| 参数 | 说明 |
|------|------|
| 配置文件路径 | 可选，指定要加载的配置文件。不指定则默认加载同目录下的 `xs.json` |

### 启动示例

```bash
# 使用默认配置文件 xs.json
xs.exe

# 指定配置文件（开发环境）
xs.exe dev.json

# 指定配置文件（生产环境）
xs.exe prod.json

# 指定配置文件（测试环境）
xs.exe test.json

# 使用绝对路径
xs.exe D:\config\myserver.json
xs.exe /etc/xserver/production.json
```

### 多环境配置管理

建议为不同环境创建独立的配置文件：

```
release/
├── xs.exe
├── xs.json          # 默认配置（开发环境）
├── xs.dev.json      # 开发环境配置
├── xs.test.json     # 测试环境配置
├── xs.prod.json     # 生产环境配置
└── wwwroot/
```

不同环境的配置差异通常包括：
- **端口** - 开发环境可能使用 8080，生产使用 80
- **调试模式** - 开发环境 `debug: true`，生产环境 `debug: false`
- **TLS** - 生产环境启用 HTTPS
- **路径** - 不同环境指向不同的脚本或资源目录

## 配置文件格式

`xs.json` 可以是以下两种格式：

1. **单服务模式** - 配置为一个对象
2. **多服务模式** - 配置为一个数组，每个元素是一个服务配置

```json
// 单服务模式
{
    "enabled": true,
    "class": "http",
    ...
}

// 多服务模式
[
    { "enabled": true, "class": "http", ... },
    { "enabled": true, "class": "mqtt", ... }
]
```

## 服务配置

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `enabled` | bool | 是 | 是否启用服务 |
| `class` | string | 是 | 服务类型（见下表） |
| `name` | string | 否 | 服务名称 |
| `desc` | string | 否 | 服务描述 |
| `param` | string | 否 | 启动参数（供脚本使用） |
| `addr` | string | 是* | 绑定地址和端口 |
| `tls` | bool | 否 | 是否启用 TLS 1.3 加密 |
| `addr_tls` | string | 否 | TLS 绑定地址和端口 |
| `host_default` | object | 是 | 默认主机配置 |
| `hosts` | array | 否 | 虚拟主机列表 |

> *注：`custom` 和 `thread` 类型时 `addr` 字段可选

### 服务类型 (class)

| 值 | 说明 |
|------|------|
| `http` | HTTP/HTTPS 服务 |
| `mqtt` | MQTT/MQTTS 服务 |
| `ws` | WebSocket/WSS 服务 |
| `xtp` | XTP 协议服务（轻量级二进制协议） |
| `tcp` | 原始 TCP 服务 |
| `udp` | UDP 服务 |
| `custom` | 自定义服务（通过回调函数实现） |
| `thread` | 线程服务（独立线程运行） |

### 地址格式

```
协议://IP地址:端口

示例：
http://0.0.0.0:80        # HTTP 监听所有 IP 的 80 端口
https://0.0.0.0:443      # HTTPS 监听所有 IP 的 443 端口
mqtt://0.0.0.0:1883      # MQTT 监听 1883 端口
tcp://127.0.0.1:9000     # TCP 监听本地 9000 端口
```

## 主机配置 (Host)

一个服务可以服务多个虚拟主机，通过 `host_default` 配置默认主机，通过 `hosts` 数组配置多个虚拟主机。

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `enabled` | bool | 是 | 是否启用主机 |
| `name` | string | 否 | 主机名称 |
| `desc` | string | 否 | 主机描述 |
| `param` | string | 否 | 启动参数（供脚本使用） |
| `host` | string | 否 | 绑定域名，多个域名用 `;` 分隔 |
| `path` | string | 是 | 主机根目录（支持相对/绝对路径） |
| `debug` | bool | 否 | 是否开启调试模式 |
| `devlang` | string | 否 | 开发语言（见下表） |
| `devfile` | string | 否 | 入口脚本文件路径 |
| `tls_ca` | string | 否 | TLS CA 证书文件路径 |
| `tls_cert` | string | 否 | TLS 证书文件路径 |
| `tls_key` | string | 否 | TLS 私钥文件路径 |
| `session` | string | 否 | Session 前缀 |

### 开发语言 (devlang)

| 值 | 说明 |
|------|------|
| `static` | 静态页面（默认值） |
| `c` | C 语言脚本（TCC 动态编译） |
| `lua` | Lua 脚本（暂不支持） |
| `js` | JavaScript 脚本（暂不支持） |

### 路径说明

- **相对路径**：以 `xs.exe` 所在目录为基准
- **绝对路径**：
  - Windows：包含 `:` 的路径，如 `D:\www`
  - Linux：以 `/` 开头的路径，如 `/var/www`

## 回调函数

当 `devlang` 设置为 `c` 时，XServer 会编译 `devfile` 指定的脚本，并调用以下回调函数：

| 函数 | 说明 | 调用时机 |
|------|------|----------|
| `ServiceInit` | 服务初始化 | 服务启动前（仅 DefaultHost） |
| `ServiceStart` | 服务启动 | custom/thread 类型启动时 |
| `ServiceUnit` | 服务清理 | 服务停止或热加载时 |
| `EventProc` | 网络事件回调 | 收到网络事件时 |
| `RequestProc` | HTTP 请求回调 | 收到 HTTP 请求时 |
| `XS_SetGlobalDate` | 全局数据传递 | 服务启动时由 XS 调用 |

### 回调函数签名

```c
// 服务初始化
void ServiceInit(XS_ServerObject objServer, XS_HostObject objHost);

// 服务启动（custom/thread）
void ServiceStart(XS_ServerObject objServer, XS_HostObject objHost);

// 服务清理
void ServiceUnit(XS_ServerObject objServer, XS_HostObject objHost);

// 网络事件回调
// 返回值：1=已处理，0=未处理（继续默认处理）
int EventProc(XS_ServerObject objServer, XS_HostObject objHost, 
              struct mg_connection* c, int ev, void* ev_data);

// HTTP 请求回调
// 返回值：1=已处理，0=未处理（继续默认处理）
int RequestProc(XS_ServerObject objServer, XS_HostObject objHost, 
                struct mg_connection* c, struct mg_http_message* hm);

// 全局数据传递
void XS_SetGlobalDate(int idx, void* ptr);
```

## 配置示例

### HTTP 服务

```json
{
    "enabled": true,
    "class": "http",
    "name": "Web Server",
    "desc": "主站点服务",
    "addr": "http://0.0.0.0:80",
    "tls": true,
    "addr_tls": "https://0.0.0.0:443",
    "host_default": {
        "enabled": true,
        "name": "默认主机",
        "path": "wwwroot",
        "tls_cert": "tls/cert.pem",
        "tls_key": "tls/key.pem",
        "devlang": "c",
        "devfile": "script/main.c"
    },
    "hosts": [
        {
            "enabled": true,
            "name": "API 服务",
            "host": "api.example.com",
            "path": "api",
            "devlang": "c",
            "devfile": "api/main.c"
        }
    ]
}
```

### MQTT 服务

```json
{
    "enabled": true,
    "class": "mqtt",
    "name": "MQTT Broker",
    "addr": "mqtt://0.0.0.0:1883",
    "tls": true,
    "addr_tls": "mqtts://0.0.0.0:8883",
    "host_default": {
        "enabled": true,
        "name": "MQTT 主机",
        "path": "mqtt",
        "tls_cert": "tls/cert.pem",
        "tls_key": "tls/key.pem",
        "devlang": "c",
        "devfile": "mqtt/main.c"
    },
    "hosts": []
}
```

## TLS 证书配置

启用 TLS 时需要配置证书文件：

```json
{
    "tls": true,
    "addr_tls": "https://0.0.0.0:443",
    "host_default": {
        "tls_ca": "tls/ca.pem",       // CA 证书（可选）
        "tls_cert": "tls/cert.pem",   // 服务器证书
        "tls_key": "tls/key.pem"      // 私钥文件
    }
}
```

每个虚拟主机可以配置独立的证书，支持 SNI（服务器名称指示）。
