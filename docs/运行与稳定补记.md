# xserver 运行与稳定补记

本文档保留这一轮稳定化里仍值得记住、但不适合继续堆在主 README 里的补记。



## 1. 路径语义

- `xs / xs.exe` 的相对配置参数，当前按可执行文件目录优先解析
- 从仓库根目录运行 `release/xs(.exe) xs_manage_test.json`，会正确加载 `release/xs_manage_test.json`
- `__xs/check_config*` 与 `__xs/reload_config*` 也复用同一套规范化后的配置路径
- `release/tcc` 下的运行时资源同样按可执行文件目录优先解析



## 2. 内置调试面结构

- `src/protocol/http.h` 现在只保留协议入口和少量 glue
- 最后的保留调试路径判定、请求校验和分发，已经统一走 `XS_HttpTryManageRequest(...)`
- 通用请求日志统一走 `XS_HttpLogRequest(...)`
- 内置调试面主链已经拆到 `src/manage/`



## 3. 稳定基线覆盖范围

当前稳定 smoke 除了冻结 production `xs` 与 `xsdbg` 的主边界外，还会继续锁住：

- `/json` 业务路由
- production `xs` 下 `__xs/status_json / __xs/dashboard / __xs/dashboard_json / __xs/bus/status` 已回到应用层
- xsdbg 内建调试入口 `__xs/status* / health* / reload* / check_config* / *_metrics* / *_clear`
- targeted reload 命中脚本编译失败时会回滚，旧 `/json` 业务路由继续可用
- `reload_json / reload_config_json` 异步回到 idle 的语义
- 仓库根目录启动
- XTP `demo.callself`
- XTP `demo.callrequeststatus`
- WebSocket echo
- custom echo

同时还冻结：

- method / `Allow`
- `Content-Type`
- xsdbg 内建调试应用的安全头
- xsdbg 未内置的 `__xs/*` 已回到应用层



## 4. 工具链补记

- `test_stable.bat` 与 `test_stable.sh` 现在都会先 build 再跑 smoke
- `test_stable.sh` 与 `tools/xs_stable_smoke.sh` 现在按实际 OS 判定 Windows / Linux 路径，不再靠仓库里是否存在 `release/xs.exe` 来分流
- `tools/xs_stable_smoke.*` 会自动清理生成的 helper 可执行文件与临时 body 文件；Linux 路径下无扩展名的 `xtp_smoke_client / ws_smoke_client / custom_smoke_client` 现在也包含在清理和 ignore 规则里
- 当前稳定 smoke 已额外锁住 `http / ws / xtp / custom` 的 `idle_timeout` 空闲连接清理回归；其中 `xsdbg` 还会继续校验对应 `*_idle_close_count`
- `XRT_MEM_DEBUG` 自动报告当前写到 `xrt_mem_report_auto.txt/json`
- `tools/xs_memdebug_check.*` 现在会把 `xsdbg` 放到临时工作目录运行；Windows 路径额外通过 `SIGBREAK` + `CTRL_BREAK` helper 进入正常停服链路
- `test_memdebug.*` 的 accepted threshold 当前按脚本真实 workload 冻结：HTTP `foreign_live_count<=900`，WS/XTP/Custom `<=840`
- 这样常规 `xsdbg` 验证不再继续写脏仓库里被跟踪的 `xrt_mem_report_auto.json`

## 6. 首页静态审查补记

- `tools/xs_stable_smoke.ps1` 与 `tools/xs_stable_smoke.sh` 现在会先跑一个 `[static-homepage]` 检查
- 这轮静态检查会锁住首页中的 xsdbg-only 直链标记：`*_metrics_json / *_metrics_clear / reload_reset / check_config_clear -> data-debug-manage="true"`
- 目标是把“首页不要重新暴露 xsdbg-only 调试入口”也纳入稳定基线，而不是继续依赖人工肉眼复扫
