## xs 持续加固：VFS 压缩输入分块读取（2026-10-26）

- 受控分配探针复现：原文仅 1 KiB、压缩区间声明 16 MiB 时，VFS 会直接申请整块输入缓冲，常驻缓存预算未覆盖这次临时分配。
- 改为最多 64 KiB 的输入分块，用 LZMA 字典接口直接写入最终输出；概率表、输出和输入缓冲分开释放。继续检查精确输入消费、原始长度和 CRC，成功后才发布缓存与记账。
- 新增 16 MiB / UINT32_MAX 声明长度的分配与读取请求探针，以及头部/输入读失败检查；真实编解码夹具覆盖跨多块的有/无结束标记流、三处分配失败、第二块缺失、截断、尾部数据及 CRC 失败清理。
- HTTP 回归增加压缩后超过 64 KiB 的包内资源，验证首次分块解码与缓存再次读取的完整内容一致。
- 验证：Windows default 通过 20 个质量步骤，Linux default 通过 21 个；站点 VFS 均为 35 项通过，归档校验分别为 66/73 项。Linux 的 xs/真实解码器通过完整 ASan/UBSan；样本编码器两源的 alignment 例外单独写入报告，范围见设计附录 B.3。候选位于 `.build/hardening-vfs-stream-20261026/`，报告为 `.build/vfs-stream-{windows,linux}-quality.json`；源码、测试输入及产物摘要一致，正式 release 未替换。

## xs 持续加固：LZMA 输入消费一致性（2026-10-26）

- 复现解包工具接受 LZMA 流后多余字节、仍以正确原文 CRC 覆盖目标文件的问题；同一输入原本已被运行时解码器拒绝。工具现同样要求完整消费条目声明的压缩输入，保持合法无结束标记 LZMA1 流的支持。
- 原生夹具以相同样本比较工具和运行时解码器，覆盖正确输入、三种尾字节、所有截断前缀及原始长度不匹配，并检查失败后的分配归零。
- 二进制回归将压缩长度扩大到下一条目的首字节后重算索引 CRC，验证解包拒绝、已有目标内容保留及无临时文件遗留。
- 验证：Windows default 通过 20 个质量步骤、66 项归档回归；Linux default 通过 21 个质量步骤（含原生 ASan/UBSan）、73 项归档回归。候选位于 `.build/hardening-lzma-20261026/`，报告为 `.build/lzma-tail-{windows,linux}-quality.json`。Windows 的符号链接和深路径环境限制仍由 Linux 对应场景补齐；正式 release 未替换。

## xs 持续加固：归档路径规则统一（2026-10-26）

- 复现 Linux 含反斜杠文件名的站点打包成功、产物却无法列表或解包的问题。打包现在于压缩前拒绝此类归档路径，保留已有输出。
- 打包、工具解析和运行时索引装载共用按显式长度进行的无分配路径校验：拒绝 NUL、反斜杠、前后或重复斜杠、`.` / `..` 分段及超出 4096 字节的条目；保留原有有效路径的接受规则。
- 新增原生非 NUL 终止视图、嵌入 NUL、长度临界值和合法点前缀检查；构造五类 CRC 自洽路径变异，分别验证解包及内嵌归档启动拒绝，并检查生产失败时原目标保留。
- 验证：Windows default 通过 20 个质量步骤、62 项归档回归；Linux default 通过 21 个质量步骤（含原生 ASan/UBSan）、69 项归档回归。候选位于 `.build/hardening-paths-20261026/`，报告为 `.build/pack-paths-{windows,linux}-quality.json`；Windows 不具备权限的符号链接及深路径夹具由 Linux 覆盖。正式 release 未替换。

## xs 持续加固：归档输入与遍历边界（2026-10-26）

- 复现并修复 Windows 下 Unicode 站点/程序路径打包失败：整体读取从窄字符 `fopen/ftell` 改为 xrt 的 UTF-8 文件接口与 64 位大小查询，支持中文和非 BMP 字符。
- 目录枚举中途错误不再作为正常结束；目录关闭失败同样停止候选，避免静默发布不完整归档。单文件 1 GiB 上限在遍历及读取阶段执行，拒绝读入期间可检测的长度变化、短读和关闭错误。
- 增加原生文件/目录故障注入，并接入现有边界检查；二进制回归增加 Unicode 路径下的五种归档操作、空文件/STORE/LZMA 往返及超限稀疏文件拒绝。
- 验证：Windows default 通过 20 个质量步骤、42 项归档回归；Linux default 通过 21 个质量步骤（含原生 ASan/UBSan）、47 项归档回归。源码、测试输入与产物摘要均核对一致；候选位于 `.build/hardening-20261025/`，报告为 `.build/hardening-{windows,linux}-quality.json`。Windows 的符号链接权限与深路径夹具仍按环境跳过，对应场景在 Linux 通过。

## xs 宿主质量加固

- 输入与文件边界：配置字符串拒绝内嵌 NUL，配置文件、字段、路径及服务/host 数量设置明确上限；路径归一化失败向上传播，候选不能带着未解析路径继续启动。
- 归档偏移统一采用不溢出的范围检查；解包校验路径排序，在锚定目录中写临时文件后改名发布，打包/剥包失败保留已有输出。
- 新增原生边界夹具，覆盖配置装配的 39 个分配失败点及资源归零；扩展归档回归覆盖偏移回绕、NUL、乱序及输出保留。
- 生命周期和预算：连接准入与退役共享活动锁；新增连接数、重载快照总字节、退役代积压、WebSocket 累积缓冲和 VFS 缓存预算。WS 两层共用有效消息上限，预算不足返回关闭码 1013；VFS 缓存发布全程互斥，移除未同步的快路径。
- Windows 原生并发及回环预算探针、生命周期和协议重载回归通过；Linux 原生夹具通过 ASan/UBSan 检查。新增 generation cookie 和 quiesce 日志便于关联终态。
- SDK ABI v1 增加原生、普通脚本和嵌套 TCC 的 72 项布局/枚举检查；补齐所有权、线程、重入和取消契约。dev_inc/dev_lib 改为逐段解析，并清理自有源码告警及内部跨翻译单元路径依赖。
- 新增可重复质量入口 `tools/check_quality.py`、摘要报告和编译期策略记录；配置夹具扩展为 57 个分配失败点、512 个变异/截断输入，并增加 VFS 并发缓存和归档原子发布失败检查。功能矩阵的发布夹具、配置和日志按进程隔离。
- 最终验证：Windows default/all 分别通过 20/21 个门禁步骤，Linux all 通过 22 个（含原生 ASan/UBSan）；归档校验 Windows 36 项、Linux 41 项通过。候选在 `.build/quality-20261025/`，来源与产物摘要一致；正式 release 未替换，未开展长时间稳定性演练。

### 构建系统

- **`all` 全选参数**：`build.bat all` / `bash build.sh all` 一键编译全部可选库。
- **`requires` 依赖自动展开**：注册表声明依赖（xsmtp/xpop3/ximap → xmail），选库阶段
  DFS 闭包展开 + 环检测；组合构建时依赖只编译注册一次，变体目录名如实展开。
- **`feature_macro` 多宏列表** 与 **`host_includes`** 两个注册表字段：多特性宏库
  （xacme）与带 include 路径的扩展无需改构建驱动。
- **xrt 模块头垫片层 SDK 常驻**（`lib/xrtshim/`）：把 `<xrt/*.h>` 模块头映射到
  `lib/xrt_decl.h` 无门控全量声明；`promote.h` 按真实 xrt.h 语义把 `XRT_MODULE_*`
  持久提升为 `XRT_FEATURE_*`。VFS 固定打包 `/xs/xrt/*.h` 与 `/xs/xrt.h`。
- xrt 升级为主线纯快照 `2639487c`（xrt 符号 2,963 → 3,030；零分叉策略见
  `lib/xrt_version.txt`）。

### 运行时

- **启动横幅与 `--version`**：`[xs] XServer 1.0.0 (commit, 日期, 平台)` + 按注册表
  顺序列出本变体扩展清单（default 显示 none）。commit/日期/平台由构建期注入，
  版本号见 `src/core/xs_version.h`。
- **契约函数 `xsExtensionEnabled(name)`**（xs 层 API 第 21 个）：运行期按注册表名
  查询扩展是否编入；大小写不敏感、requires 可见、未知名/空串/NULL 恒 false。
